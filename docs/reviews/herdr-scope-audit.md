## 兼容与状态语义

- `FILEBOX_AGENT_HERDR_ENABLED=0` 或 `false`：启动时在 PATH 查找和 --version 之前退出 Herdr 初始化；显式 FILEBOX_AGENT_HERDR 路径也无法绕过。
- Agent 不创建 HerdrClient、不上报 Herdr 能力；Hub 拒绝请求，Agent 自身也无法执行 CLI。前端不能重新开启。
- 未设置时保留自动探测；无效值按关闭处理并记录一次启动警告。改变配置后需重启 Filebox Agent；不停止独立运行的 coding agents 或 Herdr 服务。
- 不新增持久化文件、revision、修改设置接口或 WS 消息。旧 localStorage 开关已经移除。
- A 重新注册能力后丢弃旧检查迟到结果；B 的在途检查、提醒 id 和 acknowledged 保留。

## 明确仍存在的限制

- 同一个 Herdr 面板仍只允许一个输入操作等待完成；等待 A 会暂时禁用 B 的输入按钮，B 的手动读取和状态检查可继续。这是尚未拆分的输入状态，不能称为窗口完全独立。
- 自动刷新选项、换行、等待选项和草稿仍由挂载中的 HerdrView 持有，离开该页面后不会持久化；其中换行和等待选项属于整个面板。此次未宣称实现跨页面草稿恢复或所有选项按窗口保存。
- Agent 设置中的 Office preview 仍是旧的浏览器共享偏好；不属于 #101–#106 的新增变更，但它同样值得后续核对设置页面的作用域表达。
- 没有本轮真机 iOS、真实 Herdr TUI 或真实 coding model 的端到端验证。受控 fixture 证明 Filebox 的界面与 relay 行为，不能证明上游识别和滚动行为完全兼容。
